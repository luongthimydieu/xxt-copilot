# 页面存档（排障）使用说明

当采集卡住、某章解析为空、答案读不出来，或者目录扫描失败时，维护者最需要的不是截图，而是**出问题那个页面的完整结构存档**。本文说明它是什么、怎么导出、要一起反馈什么信息，以及隐私注意事项。

---

## 1. 为什么需要页面存档？

学习通在不同学校、不同课程、不同版本下，页面结构并不完全一样。扩展靠「多套解析适配器」去猜页面里哪块是题干、哪块是选项、哪块是官方答案（适配器名为 `markitem`、`timu`、`score-review`、`phone`、`questionli`、`text` 等，可在结果表的「质量 / 适配器」列看到本次用的是哪一个）。一旦遇到没见过的页面结构，就会出现：

- 题目采到了但内容错乱；
- 某章一道题都解析不出来；
- 答案列是空的；
- 采集在某个任务点卡住或报错。

只看截图，维护者无法知道页面源码里到底长什么样，也就无法写出对应的适配器。**页面存档就是把当时页面的 HTML、同源 iframe 帧信息、目录、运行日志一起打包下来的 JSON 文件**，维护者可以在自己电脑上离线复现、调试解析逻辑。它比截图信息量大得多，也更容易定位问题。

> 页面存档只保存在你本地，扩展**不会自动上传**任何内容。是否发出去、发给谁，由你决定。

---

## 2. 什么时候需要导出页面存档？

遇到以下情况之一，就建议导出一份：

| 现象 | 说明 |
| --- | --- |
| 某章「采集结果为空」 | 明明有测验，但一道题也没采到 |
| 某题解析错乱 | 题干/选项/答案明显不对，或出现乱码或加密字体警告 |
| 答案一直不显示 | 页面上能看到答案，但采集结果里答案为空 |
| 某个任务失败 | 任务状态区显示失败，日志里有 `error` / `warn` |
| 采集卡在某一页 | 进度长时间不动，日志停在某个任务 |
| 目录扫描失败或章节数不对 | 扫描结果与课程目录不一致 |
| 单页提取失败或结果不对 | 点「提取当前页」后题目数量/内容与页面不符 |

---

## 3. 导出页面存档的步骤

1. **停在出问题的页面上**：在浏览器里打开那个采集失败/解析为空的章节或任务点页面，让页面**完全加载**。如果问题是整门课的，就停在课程章节页即可。
   - 如果页面内容嵌在**同源** iframe 里也没关系：扩展会自动收集主页面和同源子帧的内容（跨域 iframe 浏览器不允许读取，会自动跳过）。
2. **打开 dashboard**：点击浏览器工具栏上的 XXT Copilot 图标，自动打开控制台（dashboard）页面。
3. **确认连接正常**：顶栏应显示课程名，状态为「已连接」。如果提示需要打开学习通页面，请回到第 1 步，确认当前标签页就是学习通课程页，再点「重新连接」。
4. **点击顶栏的「导出页面存档」**：按钮位置在「重新连接」「提取当前页」「设置」旁边。导出期间按钮会显示「导出中…」。
5. **等待下载完成**：浏览器会下载一个 JSON 文件，文件名类似：

   ```text
   xxt-snapshot-<课程名>-<时间>.json
   ```

   例如 `xxt-snapshot-组织行为学-20261018-0930.json`。
6. **检查文件是否正常**（可选）：用文本编辑器（记事本、VS Code 等）打开，能看到 `exportedAt`、`course`、`state`、`snapshot` 等顶层字段，`snapshot` 里包含 `capturedAt`、`url`、`context`、`frames`、`catalog`、`state` 就说明存档成功。**不要用 Excel 打开或修改它**。
7. **不要改文件名和内容**，原样保存，准备反馈。

> 如果按钮点了没反应：先确认 dashboard 顶栏连接状态正常（显示课程名）。如果连接异常，回到学习通课程页，点「重新连接」后再导出。

## 4. 存档里有什么？

导出的 JSON 大致结构如下（字段以便于维护者排查为准）：

| 字段 | 内容 |
| --- | --- |
| `generator` / `exportedAt` | 导出工具版本与导出时间 |
| `course` | 课程信息（课程名、courseId、clazzId、cpi、课程页 URL） |
| `state` | 导出时 dashboard 看到的采集状态，其中 `state.logs` 是运行日志 |
| `snapshot.capturedAt` / `snapshot.url` | 存档抓取时间与页面 URL |
| `snapshot.context` / `snapshot.pageTitle` | 当前课程上下文与页面标题 |
| `snapshot.catalog` | 扫描到的章节（任务点）列表 |
| `snapshot.frames` | 每个同源帧的 URL、标题、HTML 长度与 HTML 正文；单帧 HTML 过长时会被截断，并带 `truncated: true` 标记 |
| `snapshot.extensionVersion` / `snapshot.userAgent` | 扩展版本与浏览器标识（帮助复现环境） |

因此，页面存档可能包含下面这些**敏感**内容：

- 课程名称、章节名称、题目、选项、答案等**课程内容**；
- 页面上的**姓名、学号、班级、头像地址**等个人信息（如果页面上有）；
- 带参数的 **URL**（可能包含课程/班级/任务 ID，甚至临时凭证类参数）；
- 运行日志（通常包含 URL、域名、错误信息）。

**不会包含**：你的账号密码、浏览器 Cookie（扩展不会把这些写进存档）。

## 5. 反馈时应同时提供哪些信息

只有存档往往还不够，请把下面信息一起发给维护者：

1. **页面存档 JSON 文件**（不要截图代替，也不要只发其中一段）。
2. **卡住那一步的运行日志**：把 dashboard 日志区里出错前后的几条日志复制出来（或截图，保留时间、级别和完整文字），并说明是卡在「扫描目录」「发现任务」「读取题目页」「解析题目」还是「读取答案」哪一步。
3. **课程名 + 章节名 + 任务点名称**，例如：`组织行为学 / 第三章 群体规范 / 3.2 章节测验`。
4. **预期题数与实际题数**，例如：`页面显示 10 题，实际采到 0 题` 或 `预期 10 题，实际 8 题，缺第 3、7 题`；如果是单页提取，也请说明点「提取当前页」后看到的题数。
5. **出问题页面的 URL**：浏览器地址栏里的完整地址（存档里的 `snapshot.url` 也有，但请一并说明你操作的是哪一页）。
6. **浏览器名称与版本**：地址栏输入 `edge://version`（Edge）或 `chrome://version`（Chrome）查看；以及扩展版本（扩展管理页里能看到）。
7. **问题是否稳定复现**：每次都在同一章失败，还是偶发；当时网络环境（校园网 / 家里宽带 / VPN）。
8. （可选）**1～2 张截图**：dashboard 的日志区、出问题的题目页。截图只作辅助，**不能代替存档**；截图前请遮挡姓名、学号等个人信息。

---

## 6. 隐私提醒

页面存档本质上就是「把网页源码和运行日志打包」，所以请务必注意：

- **只私下发给可信的维护者**，用于排障；
- **不要上传到公开网盘、论坛、公开群聊或代码仓库**；
- 反馈前可以先用文本编辑器搜一下自己的姓名、学号，不需要的部分手动删掉再发；
- 存档文件用完可以删除，不需要长期保存。

---

## 7. 维护者拿到存档后会做什么？

维护者会把存档里的 HTML 加载进解析器离线调试，判断属于哪一类页面结构（例如 `markitem` / `timu` / `score-review` / `phone` / `questionli` / `text`），然后：

- 修正现有适配器的选择器；
- 或新增一个适配器，兼容这种页面结构；
- 把问题页面整理成测试样例，避免以后回归。

问题修复后，你只需覆盖更新扩展文件、在扩展管理页点「重新加载」，再刷新学习通页面重新采集即可。

## 8. 常见问题

**Q：点击「导出页面存档」没有任何反应？**
A：先确认 dashboard 顶栏已连接（显示课程名、状态「已连接」）。如果连接状态异常，回到学习通课程页，点「重新连接」后再导出。

**Q：下载的 JSON 用 Excel 打开是乱码？**
A：正常，请不要用 Excel 打开。用记事本、VS Code 等文本编辑器打开查看。

**Q：存档文件很大（几 MB 甚至更大）正常吗？**
A：正常。页面 HTML 本身就可能很大，尤其是包含大量题目和图片地址的页面；单帧 HTML 超过 200 万字符时会被截断并标记 `truncated`。原样发送即可，不要人为截断。

**Q：为什么存档里没有某个跨域 iframe 的内容？**
A：浏览器安全策略不允许扩展读取跨域 iframe 的 DOM，存档只包含主页面和同源子帧；这不会影响维护者排查大多数解析问题。

**Q：能不能只发其中一小段？**
A：不建议。维护者需要完整的页面结构才能复现解析过程；截断后可能刚好丢掉关键部分。

**Q：存档里会不会有我的账号信息？**
A：不会包含密码和 Cookie，但页面 HTML 里可能有姓名、学号等展示信息。请按第 6 节处理后再发送。
